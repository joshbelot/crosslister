# Architecture

A single-user, local-only crosslisting app that runs on a Mac. The **local SQLite database is the source of truth**; marketplaces are downstream targets that each hold a listing ID, URL and status.

```text
Mac
 ├── Browser tab: React UI (Vite dev server :5173, or served by backend in production)
 │        │  HTTP JSON  (/api/*)  +  Server-Sent Events (/api/events)
 ├── Node backend (Fastify, 127.0.0.1:4317)
 │        ├── SQLite  (data/crosslister.db, Drizzle ORM, better-sqlite3)
 │        ├── Photos  (data/listings/<id>/original|derived|processed/<marketplace>)
 │        ├── Job runner (sequential queue, persisted in `jobs` table)
 │        │      └── Marketplace adapters (registry)
 │        │             ├── browser adapters → Playwright persistent contexts (browser-profiles/<marketplace>/)
 │        │             ├── api adapter (eBay Trading + REST)
 │        │             └── manual adapter (OfferUp, Vinted, Etsy, Other)
 │        ├── Secrets (macOS Keychain via `security` CLI; file fallback)
 │        └── Optional AI provider (Ollama on localhost:11434; optional OpenAI-compatible/Anthropic)
 └── logs/ (daily log files)
```

## Key decisions

| Decision | Choice | Why |
|---|---|---|
| Repo layout | One npm package; `src/shared`, `src/server`, `src/web` | Simplest. No workspaces, no build step for the server (run with `tsx`). |
| Backend | Fastify 5 + TypeScript | Small, fast, good multipart + static support; Playwright runs in the same process. |
| DB | SQLite via better-sqlite3 + Drizzle ORM; migrations generated by drizzle-kit | Lightweight, synchronous, zero-config, single file to back up. |
| Money | Integer cents everywhere | No float bugs. |
| IDs | `nanoid` 12 chars (alphabet `0-9a-z`) + human SKU `CL-00001` | Short folder names; SKU for physical labels. |
| Frontend | React 19, Vite, TanStack Query, React Router, Tailwind CSS 4 | Fast to build, fast to use. |
| Live progress | Server-Sent Events | One-way server→UI push is all we need; simpler than WebSockets. |
| Automation | Playwright, **headed**, one persistent context per marketplace | User logs in once; sessions persist; user can take over any time. |
| Publish policy | App fills; **user clicks the final button by default** (`autoSubmit` off; forced off for Facebook) | ToS risk reduction, correctness, user stays in control. |
| Failure policy | A field that can't be filled becomes a *needs your attention* item, not a crash | Uncalibrated or changed selectors still produce a useful assisted flow. |
| eBay | Trading API (XML) for create/revise/end/status/import; REST for taxonomy/metadata/account policies | Listings stay editable on ebay.com; one API family for CRUD. See research §2.5. |
| Photos | Originals stored byte-for-byte; edits (rotate/crop) are non-destructive metadata; derived + per-marketplace JPEGs generated on demand with metadata (incl. GPS) stripped | Never lose quality; privacy. |
| Secrets | `.env` for app credentials (eBay client id/secret); OAuth refresh token in macOS Keychain | Nothing sensitive in git or plaintext DB. |
| AI | Optional, off by default; local Ollama preferred | No paid dependency; suggestions always reviewed by the user. |
| Security | Bind 127.0.0.1 only; Host/Origin checks on every request | The API can drive logged-in browsers — block DNS-rebinding/CSRF from other websites. |

## Core data flow

```text
Listing (canonical, SQLite)
   │  user selects marketplaces → marketplace_listings rows (status not_listed)
   │  validation = canonical rules + adapter.validate(effectiveListing)
   ▼
POST /api/listings/:id/crosslist → one Job per marketplace (NOT_STARTED)
   ▼
Job runner (sequential) → adapter.publish(ctx)
   │   ctx.step(...) → job_steps rows → SSE → progress UI
   │   ctx.requestUser(...) → job NEEDS_USER → SSE → "needs attention" card → POST /continue
   ▼
SUCCESS: marketplace_listings.status=active, remote_id, url  → listing status recomputed
FAILED : marketplace_listings.status=error, last_error; listing NOT marked listed
```

## Modules

- `src/shared/` — types, zod schemas, taxonomy, colors, constants used by both server and web.
- `src/server/db/` — Drizzle schema, connection, migrations.
- `src/server/services/` — listings, photos, image processing, settings, validation, jobs, events, logger, secrets, export, duplicates.
- `src/server/routes/` — thin Fastify route handlers calling services.
- `src/server/marketplaces/` — adapter interface, registry, one folder per marketplace. Core code never imports a specific adapter except `registry.ts`.
- `src/server/browser/` — browser manager (persistent contexts) and resilient locator/fill helpers.
- `src/server/importers/` — import pipeline, extractors, duplicate detection.
- `src/server/ai/` — provider abstraction + prompts.
- `src/web/` — React app.

The full, step-by-step build plan is in [`docs/spec/`](spec/README.md).
