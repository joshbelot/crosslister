# 09 — Optional AI (M35–M38)

AI is **off by default** and the app must be fully usable without it. No feature depends on a paid API. Suggestions are always shown for review and applied only when the user clicks **Use**. AI must never invent facts.

## 1. Providers (`src/server/ai/provider.ts`)

```ts
export interface AiRequest { system: string; prompt: string; images?: string[] /* absolute file paths */; json: boolean; maxTokens?: number }
export interface AiProvider { name: string; health(): Promise<{ ok: boolean; message: string; models?: string[] }>; complete(req: AiRequest): Promise<string> }
export function getProvider(settings: Settings): AiProvider; // throws AppError('AI_DISABLED', 400, 'AI is turned off in Settings.') when disabled
```

- **Ollama** (`ollama.ts`, default): `POST {baseUrl}/api/chat` `{ model, stream: false, format: json ? 'json' : undefined, messages: [{ role: 'system', content: system }, { role: 'user', content: prompt, images: base64[] }], options: { temperature: 0.2 } }` → `message.content`. Images: the photo's `display` JPEG, base64, max 4. Health: `GET {baseUrl}/api/tags` → model names; ok if `textModel` is present (message "Model gemma3:4b not found. Run: ollama pull gemma3:4b").
- **OpenAI-compatible** (`openaiCompatible.ts`, e.g. LM Studio): `POST {baseUrl}/chat/completions` with `Authorization: Bearer <OPENAI_COMPATIBLE_API_KEY or 'local'>`, images as `image_url` data URLs, `response_format: { type: 'json_object' }` when `json`. Health: `GET {baseUrl}/models`.
- **Anthropic** (`anthropic.ts`, optional, paid): `POST https://api.anthropic.com/v1/messages` with headers `x-api-key: ANTHROPIC_API_KEY`, `anthropic-version: 2023-06-01`; model from `textModel` (the user types the current model name from Anthropic's docs; when switching provider to Anthropic, the UI clears the model fields and shows the placeholder "Enter an Anthropic model name"); images as base64 `image` blocks. Health: key present + a 1-token test call. Settings UI warns "Uses a paid API".
- Timeout 120 s (local models are slow). Errors → `AppError('AI_ERROR', 502, "The AI model didn't respond: <reason>")`.

JSON handling: `parseJsonLoose(text)` strips code fences, takes the first `{…}` block, `JSON.parse`, then validates with the feature's zod schema; on failure retry once with "Return only valid JSON." appended; then `AI_ERROR`.

## 2. Settings & health (M35)

Settings fields: 02 §5.1 `ai`. Route `GET /api/ai/health` → provider `health()`. When `ai.enabled` is false the editor hides all ✨ buttons.

## 3. Shared system prompt (`prompts.ts`)

```text
You help a person write listings for second-hand items they are selling.
Rules:
- Use ONLY facts given in the item details or clearly visible in the photos. Never invent brand, size, materials, measurements, defects, model names, dates or history.
- If something is unknown, leave it out. Do not guess.
- Be honest about condition and flaws exactly as provided.
- No emojis, no hashtags unless asked, no ALL CAPS, no claims like "authentic" or "rare" unless provided.
- Respond in the exact JSON format requested.
```

Item details are rendered as a plain list: `Title`, `Brand`, `Model`, `Category` (path label), `Size`, `Colors`, `Material`, `Condition` (label + hint), `Condition notes`, `Measurements`, `Tags`, `Seller's notes for the description` (the current description text). Empty fields omitted.

## 4. Features

All routes are `POST`, body `{ listingId }` plus noted fields, and return suggestions only (nothing is saved).

### 4.1 Description — `POST /api/ai/description` (M36)
Prompt: "Write a clear, friendly listing description of 3–6 short sentences followed by a bullet list of key details. Mention every flaw from the condition notes. Return JSON {\"description\": string}." Response `{ description }`. UI: ✨ next to Description → popover shows the text, **Use** (replaces), **Append**, **Dismiss**.

### 4.2 Title — `POST /api/ai/titles` (M36)
Prompt: "Suggest 3 search-friendly titles of at most {maxLen} characters (brand, item type, key attributes like size and color, in that order). Return JSON {\"titles\": string[]}." `maxLen` = smallest `titleMaxLength` among selected marketplaces (default 80). Server drops titles longer than `maxLen` and those containing words not present in the item details (case-insensitive, ignoring stop words and common item-type words from the canonical category labels). UI: ✨ next to Title → list of 3 with **Use**.

### 4.3 Attributes from photos — `POST /api/ai/attributes` (M37)
Uses `visionModel` with the first 4 photos. Prompt includes the list of allowed canonical category ids with labels and allowed color ids. "Identify only what you can clearly see. Return JSON {\"brand\": string|null, \"categoryId\": string|null, \"colors\": string[], \"size\": string|null, \"itemType\": string|null, \"evidence\": {\"brand\"?: string, \"size\"?: string}}. Only report size if it is readable on a tag in a photo." Server validation: `categoryId` must be selectable (else null); colors filtered to `COLOR_IDS` (max 2); `brand`/`size` require non-empty `evidence` (else null). UI: ✨ **Suggest from photos** button under the photo grid → a card listing each suggested value with its evidence and per-field **Use** checkboxes + **Apply selected**. Never fills fields automatically.

### 4.4 Marketplace-specific versions — `POST /api/ai/marketplace-copy` (M38)
Body `{ listingId, marketplaceIds }`. For each marketplace: "Rewrite the title (max {titleMax} chars, or none if null) and description (max {descMax} chars) for {N}. Style: {style}. Keep all facts and flaws. Return JSON {\"title\": string|null, \"description\": string}." Styles: Mercari "concise, keyword-rich"; Poshmark "friendly, fashion-focused"; Depop "casual, short lines, up to 5 relevant hashtags at the end"; Facebook "plain and local, mention pickup or shipping per seller's notes"; eBay "detailed, factual, item-specifics style"; Grailed "brand/designer-first, menswear vocabulary"; others "neutral". Response `{ items: Array<{ marketplaceId, title, description }> }` validated against limits. UI: in `MarketplaceOverridesPanel` a ✨ **Write versions for all marketplaces** button → per tab shows the suggestion with **Use as override**.
